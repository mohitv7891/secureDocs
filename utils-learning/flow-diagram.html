IBE SecureDocs: User1 Sends File to User2 — Complete E2E Flow

🔐 KDC Server — Port 5007

Purpose: Key Distribution Center — handles identity, trust, and cryptographic key lifecycle.

  • User registration & OTP verification
  • Runs native C keygen binary to produce IBE private keys
  • Encrypts IBE key with user's password (PBKDF2 + AES-GCM)
  • Emails .dat key file to user
  • Login / JWT token issuance
  • MongoDB stores: {email, bcryptHash, kdfSalt}
  • ❌ Does NOT store files or encryptedKeyPkg

Routes: /api/auth/*

🗄️ Data Server — Port 5006

Purpose: Encrypted document storage — a dumb store, never sees plaintext.

  • Receives & stores encrypted file blobs (ciphertext only)
  • Lists files for a recipient by email
  • Serves ciphertext for download
  • Verifies JWT from KDC to authenticate requests
  • MongoDB stores: {originalFileName, encryptedData, senderId, recipientId}
  • ❌ Never sees plaintext, never handles crypto keys

Routes: /files/*

❓ Why Two Separate Servers?

  • Separation of concerns: KDC holds secrets (keys, passwords); Data Server holds ciphertext. Compromising one does not compromise the other.
  • Principle of least privilege: Data Server has zero knowledge of crypto — it cannot decrypt anything even if fully breached.
  • Independent scaling: File storage and key management have different load profiles.
  • Security boundary: If the Data Server is breached, attackers get only useless ciphertext blobs.
Which server is hit when?  |  ■ KDC :5007 → Register, Verify OTP, Login, Get JWT  |  ■ Data Server :5006 → Upload encrypted file, List received files, Download encrypted file  |  Both servers share the same JWT_SECRET to validate tokens cross-server.
